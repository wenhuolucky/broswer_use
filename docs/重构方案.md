## 三、分层设计原则

### 3.1 分层架构

```
┌─────────────────────────────────────────┐
│            entry/ 启动入口层              │
│  职责：解析参数、加载配置、启动服务        │
│  调用：service 层                        │
└─────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────┐
│            service/ 业务服务层            │
│  职责：编排多个 domain 和 infrastructure │
│  调用：domain, platform, infrastructure │
└─────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────┐
│           domain/ 核心业务模型层          │
│  职责：业务规则、实体定义                │
│  调用：无（核心层）                      │
└─────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────┐
│           platform/ 平台接入层            │
│  职责：封装平台差异                      │
│  调用：domain                           │
└─────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────┐
│        infrastructure/ 外部依赖层         │
│  职责：封装 HTTP、文件、浏览器等外部依赖  │
│  调用：无                               │
└─────────────────────────────────────────┘
```

### 3.2 调用边界

| 层级 | 可调用 | 被调用 |
|------|--------|--------|
| entry | service | - |
| service | domain, platform, infrastructure | entry |
| domain | - | service |
| platform | domain | service |
| infrastructure | - | service |

## 八、注意事项

### 8.1 重构原则

1. **不要推倒重来** - 渐进式重构，每次只改一处
2. **保持功能可用** - 每一步完成后立即测试
3. **先独立后组合** - 先拆分再重组
4. **测试覆盖** - 关键路径有测试

### 8.2 常见问题

**Q: 如何处理跨模块依赖？**
A: 通过依赖注入解决，让调用方传入依赖而非在内部创建。

**Q: 如何处理配置文件？**
A: 统一使用 `config/env.py` 加载，模块只接收配置对象。

**Q: 如何验证重构没有破坏功能？**
A: 每次修改后运行 `python -m entry.cli <命令>` 验证功能正常。
