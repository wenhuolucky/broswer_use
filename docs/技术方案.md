# 技术方案

## 1. 项目概述

### 1.1 项目目标

实现两个独立的浏览器自动化模块：

1. **头条号自动发布** — 实现头条号（mp.toutiao.com）文章的自动化发布，通过 AI Agent 驱动本地 Edge 浏览器操作，替代人工手动发文流程。
2. **豆包循环问答** — 自动向豆包发送问题并收集回复，用于测试 AI 生成内容的检测性。

### 1.2 核心需求

- 使用本地 Microsoft Edge 浏览器（非第三方 stealth Chromium）
- 自动登录并保存 cookie 到本地文件
- 自动填写文章标题和正文内容
- 支持文章配图上传（封面通过本地上传 + 正文图片预上传到 CDN）
- 自动处理发布过程中的弹窗和引导
- 支持多用户并发发布
- 豆包模块支持循环问答、人类行为模拟、数据持久化

## 3. 核心流程设计

### 3.1 登录流程 (`--setup`)

```
1. 通过 playwright.chromium.launch_persistent_context() 启动 Edge 浏览器
2. 导航到 mp.toutiao.com
3. 等待用户手动完成登录（扫码/账号密码）
4. 用户按 Enter 后调用 context.storage_state() 保存 cookie
5. 保存到 auth.json（Playwright storage_state 格式）
6. 关闭浏览器（context.close() + playwright.stop()）
```

### 3.2 发文流程 (`--publish`)

```
1. 验证 auth.json 存在且包含头条号 cookie
2. 如果有图片：
   ├── 第一张（封面）：保留本地文件路径，由 Agent 在 Edge 中通过本地上传设置
   └── 其余图片（正文）：通过 toutiao_uploader 预上传到 CDN，获取 URL 列表
3. 启动 Edge 浏览器（launch_persistent_context + CDP 端口）
4. 通过 CDP 获取 WebSocket URL，创建 BrowserSession
5. 创建 Agent（绑定 DeepSeek LLM，注册 available_file_paths）
6. 执行 Agent.run(max_steps=80)
   ├── 导航到头条号发布页面
   ├── 填写标题
   ├── 填写正文（通过 contenteditable DOM 注入）
   ├── 在正文中插入图片（Agent 操作图片上传）
   ├── 设置封面（点击封面"+" → "本地上传" → 选择本地文件）
   ├── 点击"预览并发布"
   ├── 处理确认对话框
   └── 验证发布结果
7. 关闭浏览器（session.close() + playwright.stop()），输出结果
```

### 3.3 图片上传流程

**正文图片（预上传）：**

```
1. toutiao_uploader.py 启动无头 Edge 浏览器，加载 auth.json 登录态
2. 导航到发布页面（https://mp.toutiao.com/profile_v4/graphic/publish）
3. 关闭 AI 助手弹窗遮罩
4. 点击编辑器工具栏的图片按钮（第 12 个按钮，.syl-toolbar-button:nth(11)）
5. 弹出图片上传抽屉（.mp-ic-img-drawer）
6. 通过 input[type="file"] 设置文件完成上传
7. 头条号后端返回上传后的图片 URL（CDN 地址）
8. 如需插入正文：点击"确定"按钮，图片插入编辑器
9. 关闭浏览器，返回图片 URL
```

**封面图片（Agent 本地上传）：**

```
1. Agent 在封面设置区域找到并点击"+"号图标
2. 弹出图片选择对话框
3. Agent 点击对话框中的"本地上传"按钮
4. 触发隐藏的 file input 元素
5. Agent 通过 upload_file 动作上传本地文件
   （文件路径需在 Agent 的 available_file_paths 中注册）
6. 头条号后端返回上传后的图片 URL
7. 封面预览显示，关闭对话框
```

## 4. 关键技术细节

### 4.1 头条号编辑器分析

头条号使用基于 **ProseMirror** 的富文本编辑器（SylJS），编辑器核心特征：

| 特征 | 值 |
|------|-----|
| 编辑器容器 | `div.ProseMirror` |
| 工具栏按钮 | `button.syl-toolbar-button`（共 24 个） |
| 图片按钮 | 索引 #11（SVG 图标为图片/山形） |
| 图片上传抽屉 | `.mp-ic-img-drawer` |
| 文件输入 | `input[type="file"]`（`accept="image/*"`） |
| 上传 API | POST `/spice/image` |
| 上传后 CDN | `image-tt-private.toutiao.com` |

### 4.2 AI Agent 任务指令设计

Agent 通过自然语言指令操作浏览器，任务指令包含导航、登录验证、标题填写、正文输入、封面设置、发布确认等完整步骤。

**关键技术：**
- 正文内容用 `<content>` XML 标签包裹，防止内容中的特殊字符干扰指令
- 正文图片 URL 以列表形式提供，Agent 负责在正文适当位置插入
- 封面图片使用本地文件路径，通过 `available_file_paths` 注册给 Agent
- Agent 的封面上传流程拆分为 5 个明确步骤（"+" → 对话框 → "本地上传" → file input → 上传）

### 4.3 available_file_paths 机制

browser-use 有一个安全限制：Agent 只能通过 `upload_file` 动作上传在 `available_file_paths` 参数中**预先注册过**的文件路径。

### 4.4 auth.json 验证机制

在发文前对 auth.json 进行三重验证：文件存在性、JSON 格式、头条号 cookie 域名检测。

### 4.5 Edge 浏览器启动方式

使用 Playwright 原生的 `chromium.launch_persistent_context()` 启动本地 Edge：

```python
from playwright.async_api import async_playwright

playwright = await async_playwright().start()
ctx = await playwright.chromium.launch_persistent_context(
    user_data_dir=str(user_data_dir),
    headless=False,
    executable_path=get_edge_path(),
    args=[f"--remote-debugging-port={cdp_port}"],
    viewport={"width": 1280, "height": 900},
)
```

Edge 路径检测优先读取 `.env` 中 `BROWSER_EXECUTABLE_PATH`，其次检测常见安装路径。

### 4.6 CDP 连接机制

浏览器启动后通过 HTTP 查询 `localhost:{port}/json` 获取 WebSocket 调试 URL，传递给 `BrowserSession` 供 Agent 控制。

```python
def get_cdp_url(cdp_port: int, max_retries: int = 10) -> str:
    ws_url = None
    for _ in range(max_retries):
        resp = urllib.request.urlopen(f"http://localhost:{cdp_port}/json", timeout=3)
        pages = json.loads(resp.read())
        if pages:
            ws_url = pages[0].get("webSocketDebuggerUrl")
            if ws_url:
                break
        time.sleep(0.5)
    return ws_url
```

### 4.7 多用户并发机制

- **跨用户并发**：通过 `asyncio.gather(*tasks)` 实现，不同用户独立进程
- **同用户串行**：通过 per-user `asyncio.Lock` 排队，防止同用户冲突
- 每个用户独立配置：auth 文件、Chrome profile 目录、CDP 端口

### 4.8 豆包模块：反检测机制（多层）

为降低豆包风控检测风险，系统实现了**四层反检测**策略：

#### 第一层：浏览器启动参数

在 `_launch_edge()` 中配置：

```python
launch_args = [
    f"--remote-debugging-port={cdp_port}",
    "--disable-blink-features=AutomationControlled",  # 关键：移除 navigator.webdriver
    "--disable-features=IsolateOrigins,site-per-process",
    "--start-maximized",
    "--no-default-browser-check",
    "--no-first-run",
]
launch_kwargs = {
    "no_viewport": True,
    "ignore_default_args": ["--enable-automation"],  # 去掉"自动测试软件控制"提示
}
```

#### 第二层：启动时注入 Stealth 脚本

`_launch_edge()` 中通过 `ctx.add_init_script(_STEALTH_INIT_SCRIPT)` 在页面加载前注入 JS，覆盖：
- `navigator.webdriver` → `undefined`（最常见检测点）
- `navigator.plugins` → 伪造长度（无头浏览器通常为空）
- `navigator.languages` → 伪造 `['zh-CN', 'zh', 'en']`
- 清理 `window.cdc_*` 变量（Selenium/Playwright 标记）
- 补全 `window.chrome.runtime` 对象
- 覆盖 `navigator.permissions.query`

#### 第三层：CDP 连接后注入（方案 B 专用）

`create_browser_session()` 中通过 `_inject_stealth_script()`，使用 CDP `Runtime.evaluate` 向已运行的 Edge 进程注入同等级反检测脚本。这确保**手动启动的浏览器**（`start_edge.bat`）在脚本附加后同样被覆盖自动化痕迹：

```python
async def create_browser_session() -> BrowserSession:
    cdp_url = get_cdp_url(EDGE_CDP_PORT)
    session = BrowserSession(cdp_url=cdp_url)
    await session.connect()
    await _inject_stealth_script(session)  # CDP 注入
    return session
```

#### 第四层：随机人类行为模拟

1. **随机行为指令**：每轮从 5 种行为中随机选一种注入 Agent 任务：
   - 向下滚动 2-3 屏，停留 3-5 秒
   - 鼠标缓慢移动，模拟人类轨迹
   - 上下滚动 1-2 次，模拟阅读节奏
   - 停留 3-6 秒观察页面
   - 下滚一屏再上回滚一小段

2. **随机延迟**：每轮完成后等待 1-5 秒再进入下一轮

#### 第五层：手动启动 Edge（CDP 附加模式）

用户通过 `doubao/start_edge.bat` 手动启动 Edge，脚本只通过 CDP 附加。浏览器进程完全由用户管理，Playwright 不参与启动，避免任何 Playwright 启动痕迹。

### 4.9 编码兼容

Windows 控制台默认 GBK 编码，通过 `sys.stdout.reconfigure(encoding="utf-8")` 解决 emoji 输出问题。

## 5. 错误处理

| 错误场景 | 处理方式 |
|----------|----------|
| auth.json 不存在 | 提示用户运行 `--setup` |
| auth.json 格式无效 | 提示用户重新运行 `--setup` |
| auth.json 无头条号 cookie | 提示可能过期，需重新登录 |
| API Key 未配置 | 提示前往对应平台获取 |
| 内容文件不存在 | 提示文件路径错误 |
| 图片上传失败 | 跳过该图片，继续发布流程 |
| 发布被头条号拦截 | Agent 自动识别并报告原因 |
| browser-use API 版本差异 | 用 try/except 兼容不同版本的 history 接口 |
| 文件上传被拒绝 | 通过 `available_file_paths` 预先注册文件路径 |

## 6. 安全与检测分析

### 6.1 反检测机制一览

| 层级 | 手段 | 作用 | 检测绕过 |
|---|---|---|---|
| **启动参数** | `--disable-blink-features=AutomationControlled` | 移除 Blink 引擎的自动化标记 | `navigator.webdriver=true` |
| **启动参数** | `ignore_default_args: ["--enable-automation"]` | 去掉地址栏"由自动测试软件控制"提示 | 视觉检测 |
| **启动注入** | `add_init_script(_STEALTH_INIT_SCRIPT)` | 页面加载前覆盖自动化痕迹 | `navigator.webdriver`、`cdc_`、`plugins`、`languages` |
| **CDP 注入** | `Runtime.evaluate(stealth_js)` | 对已运行的 Edge 进程注入同等级反检测 | 同"启动注入"，覆盖方案 B 场景 |
| **手动启动** | 用户通过 bat 启动，脚本只 CDP 附加 | 绕过 Playwright 启动流程 | Playwright 启动指纹、进程参数 |
| **行为模拟** | 随机滚动/鼠标轨迹/停留（5 种）+ 1-5s 随机延迟 | 打破固定节奏 | 行为模式检测 |

### 6.2 豆包侧可见特征

| 检测维度 | 是否可检测 | 说明 |
|---|---|---|
| **navigator.webdriver** | ❌ 不可检测（已被覆盖为 undefined） | 最常见检测点，已绕过 |
| **cdc_ 变量痕迹** | ❌ 不可检测（已清理） | Selenium/Playwright 标记 |
| **plugins / languages** | ❌ 不可检测（已伪造） | 无头浏览器通常 plugins 为空 |
| **CDP 协议连接** | ⚠️ 理论上可检测 | 网站可检测 devtools 连接，但手动开 devtools 也会触发 |
| **行为模式** | ⚠️ 部分可检测 | 随机行为模拟已降低风险，但固定间隔提问仍可疑 |
| **IP/设备特征** | ❌ 不可检测 | 在本机运行，IP 和设备指纹都是真实的 |
| **账号行为频率** | ⚠️ 可检测 | 同账号高频问答仍是最大风险因素 |

### 6.3 降低风险的实操建议

- `--interval` 建议 ≥ 120 秒（当前默认 60 秒偏高）
- 避免长时间不间断运行，建议设 `--max-iterations` 分批跑
- 文章内容建议进行人工润色，降低 AI 写作痕迹
- 如再次触发验证码，可考虑方案 B + 拉长间隔 + 随机化间隔（interval ± random(0, 15)）

## 7. 限制与约束

### 7.1 已知限制

- **头条号账号限制**：需完成实名认证才能发布文章
- **浏览器依赖**：仅支持 Windows 系统的 Microsoft Edge 浏览器
- **cookie 有效期**：auth.json 中的 cookie 会过期，需定期重新登录
- **Agent 可靠性**：AI Agent 对页面结构变化敏感，头条号 UI 更新可能导致操作失败

### 7.2 不支持的功能

- 定时发布
- 视频发布
- 评论管理
- 数据统计

## 8. 后续优化方向

1. **封面上传优化**：探索头条号封面设置的 API 接口，减少 Agent 操作步骤
2. **正文图片插入优化**：将正文图片预上传和插入集成到发文流程，减少 Agent 决策
3. **账号过期检测**：增加发布前登录态有效性检测，自动触发重新登录
4. **日志系统**：用 logging 模块替代 print，支持文件日志和分级输出
5. **重试机制**：Agent 失败时自动重试，提高成功率
6. **反检测加码**：增加无目的浏览动作（翻历史、点侧栏）、鼠标悬停模拟、请求间隔抖动（interval ± random(0, 15)）
7. **CDP 截图超时优化**：Agent 运行后关闭截图存档步骤，避免 `ScreenshotWatchdog` 15s 超时卡顿
